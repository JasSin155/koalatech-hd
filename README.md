# KoalaTech Course Platform: GitOps with Argo CD, Key Vault Workload Identity and CI security gates

SIT722 Task 10.3HD. This repository is the application and infrastructure half of the project. The deployment half lives in [koalatech-gitops](https://github.com/JasSin155/koalatech-gitops).

## What this project adds on top of the Week 8 to 10 pipeline

1. **Pull-based GitOps deployment.** Argo CD runs inside AKS and continuously reconciles the `production` namespace to the `koalatech-gitops` repository, including reverting manual `kubectl` changes. The CI pipeline no longer has any access to the cluster.
2. **Secrets that never touch Git, Terraform state or Kubernetes Secret objects.** Key Vault holds every application secret. Pods authenticate to it with Azure AD Workload Identity (a federated ServiceAccount token, no password) and the Secrets Store CSI driver mounts the values as files.
3. **Passwordless CI.** GitHub Actions logs in to Azure through OIDC federation to a managed identity that only holds `AcrPush`. There is no `AZURE_CREDENTIALS` secret.
4. **Two blocking security gates.** checkov scans the Terraform module and Docker Scout scans every image. A failure in either stops the image from being pushed or deployed.

## Flow

```
git push (main) ──> CI: checkov gate + unit tests ──> build image ──> Docker Scout gate ──> push to ACR
                                                                                    │
                                   commit new image tag to koalatech-gitops <───────┘
                                                    │
                    Argo CD (in AKS) detects commit, syncs production namespace
                                                    │
                  pods start as koalatech-sa ──> Workload Identity token exchange ──> Key Vault ──> CSI mount
```

## Repository layout

| Path | Purpose |
|---|---|
| `*-service/`, `frontend/` | Application code, unchanged from week08 |
| `terraform/` | AKS (OIDC issuer, Workload Identity, Key Vault CSI add-on), ACR, Key Vault, managed identities, storage |
| `.checkov.yaml` | checkov gate configuration, every accepted finding listed with its reason |
| `.github/workflows/ci.yml` | Test, scan, build, push, then hand-off to GitOps |
| `scripts/` | Operator scripts: `prep-azure`, `seed-secrets`, `render-gitops`, `github-settings`, `bootstrap-argocd`, `verify-no-secrets`, `teardown` |

## Running it

All scripts run from the repository root in Git Bash, with `koalatech-gitops` cloned next to this repository.

```bash
bash scripts/prep-azure.sh                 # resource group + User Access Administrator on it
cd terraform && terraform init && terraform apply && cd ..
bash scripts/seed-secrets.sh               # secrets go straight into Key Vault
bash scripts/render-gitops.sh              # fill non-secret ids into the GitOps manifests
bash scripts/github-settings.sh            # prints the GitHub variables to add
bash scripts/bootstrap-argocd.sh           # install Argo CD and register the Application
bash scripts/verify-no-secrets.sh          # prove the password is only in Key Vault and the pod
bash scripts/teardown.sh                   # delete everything
```

## Known limitation

The storage account access key is generated by Azure and recorded by the azurerm provider in `terraform.tfstate` as an attribute of the storage account. The application reads the connection string from Key Vault, but the key still exists in local state, so state is kept local, gitignored and deleted at teardown. Moving the photo storage code to Workload Identity would remove this.
